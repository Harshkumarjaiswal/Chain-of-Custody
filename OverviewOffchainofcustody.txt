1. PROJECT PURPOSE
================================================================================

The Digital Chain of Custody system is a forensic evidence management platform
designed for law enforcement agencies, cyber crime units, and digital forensics
teams. It provides a secure, auditable, and structured environment to manage
digital evidence from collection to court presentation.

The system ensures:
  - Tamper-evident evidence storage with SHA-256 hash verification
  - Complete chain of custody logging for every action on evidence
  - Role-based access control for different team members
  - Secure OTP-based authentication for login and registration
  - AI-powered investigation summarization using Groq (LLaMA 3.3 70B)
  - PDF report generation for forensic cases
  - Support for large evidence files up to 10GB

2. TECHNOLOGY STACK
================================================================================

BACKEND
-------
  Runtime         : Node.js
  Framework       : Express.js v4
  Database        : MongoDB (via Mongoose ODM)
  Authentication  : JWT (JSON Web Tokens) + OTP via Nodemailer (Gmail SMTP)
  File Uploads    : Multer (disk storage, up to 10GB)
  Password Hashing: bcryptjs (salt rounds: 12)
  AI Integration  : Groq SDK (LLaMA 3.3 70B model)
  PDF Generation  : PDFKit
  Logging         : Morgan

FRONTEND
--------
  Framework       : React 19 + Vite 8
  Routing         : React Router DOM v7
  HTTP Client     : Axios (1 hour timeout for large file operations)
  Icons           : React Icons (HeroIcons set)
  State Management: React Context API (AuthContext)

INFRASTRUCTURE
--------------
  Version Control : Git / GitHub
  OTP Email       : Gmail SMTP via Nodemailer
  AI API          : Groq Cloud (free tier, 14,400 req/day)
  File Storage    : Local disk (server/uploads/)

  Authentication Flow:
  --------------------
  Registration:
    User fills form --> POST /api/auth/register/send-otp
    --> OTP emailed via Gmail --> User enters OTP
    --> POST /api/auth/register/verify-otp --> Account created --> JWT issued

  Login:
    User enters email + password --> POST /api/auth/login
    --> Credentials verified --> OTP emailed --> User enters OTP
    --> POST /api/auth/verify-otp --> JWT issued --> Session started

6. CORE FEATURES
================================================================================

6.1 OTP-BASED AUTHENTICATION
  - Two-factor authentication for both registration and login
  - OTP generated as 6-digit random number, valid for 10 minutes
  - Sent via Gmail SMTP using Nodemailer
  - Styled HTML email with "DIGITAL-CHAIN-OF-CUSTODY" branding
  - OTP stored in MongoDB with expiry, cleared after single use

6.2 EVIDENCE MANAGEMENT
  - Upload forensic evidence files up to 10GB
  - Supported categories: disk-image, log-file, document, memory-dump,
    network-capture, mobile-data, other
  - Acquisition tools tracked: FTK Imager, Autopsy, EnCase, Other
  - SHA-256 hash generated on upload using streaming (memory efficient)
  - Integrity verification compares stored hash vs current file hash
  - Upload progress bar for large files (real-time %)
  - Streaming download with custody log entry on each download

6.3 CHAIN OF CUSTODY
  - Every action on evidence is logged: uploaded, accessed, downloaded,
    verified, transferred
  - Logs include: timestamp, user, IP address, action details, hash values
  - Immutable audit trail viewable on evidence detail page
  - Timeline view in the UI

6.4 AI INVESTIGATION SUMMARIZATION
  - Powered by Groq API (LLaMA 3.3 70B model)
  - Analyzes all findings for an evidence item
  - Generates structured forensic report with:
      * Investigation overview
      * Key observations and patterns
      * Analysis results and significance
      * Conclusions
      * Recommended next steps
  - Summary saved to evidence record in database

6.5 USER PROFILE
  - Avatar upload (image files, max 2MB)
  - Bio and department fields
  - Work history with job title, organization, date range
  - Experience level auto-detected from work history dates:
      < 2 years  --> Junior
      2-4 years  --> Mid
      4-7 years  --> Senior
      7-10 years --> Lead
      10+ years  --> Expert
  - Files tab showing assigned tasks and uploaded evidence
  - Password change with current password verification

6.6 TASK MANAGEMENT
  - Admin/supervisor can assign tasks to officers/analysts
  - Tasks linked to cases with priority and due date
  - Status tracking: pending, in-progress, completed

6.7 PDF REPORT GENERATION
  - Full forensic case report generated as PDF
  - Includes case details, evidence list, custody logs, findings
  - Downloadable directly from case detail page

6.8 LARGE FILE SUPPORT
  - Multer file size limit: 10GB
  - Server HTTP timeout: 1 hour
  - Axios request timeout: 1 hour
  - Hash generation uses Node.js streams (no memory bottleneck)
  - File download uses fs.createReadStream (no memory bottleneck)

7. API ENDPOINTS SUMMARY
================================================================================

AUTH
  POST   /api/auth/register/send-otp      Send OTP for new registration
  POST   /api/auth/register/verify-otp    Verify OTP and create account
  POST   /api/auth/login                  Verify credentials, send login OTP
  POST   /api/auth/verify-otp             Verify login OTP, return JWT
  GET    /api/auth/me                     Get current user
  PUT    /api/auth/profile                Update profile (bio, level, history)
  PUT    /api/auth/change-password        Change password
  POST   /api/auth/avatar                 Upload profile picture
  GET    /api/auth/users                  List all users (admin only)
  PUT    /api/auth/users/:id/role         Update user role (admin only)
  PUT    /api/auth/users/:id/toggle       Toggle user active status (admin only)

CASES
  GET    /api/cases                       List all cases
  POST   /api/cases                       Create new case
  GET    /api/cases/:id                   Get case detail
  PUT    /api/cases/:id                   Update case
  DELETE /api/cases/:id                   Delete case
  GET    /api/cases/stats/overview        Dashboard statistics

EVIDENCE
  GET    /api/evidence/case/:caseId       Get evidence for a case
  GET    /api/evidence/detail/:id         Get evidence detail (logs access)
  POST   /api/evidence/upload/:caseId     Upload evidence file
  GET    /api/evidence/download/:id       Download evidence file (logs download)
  POST   /api/evidence/verify/:id         Verify SHA-256 integrity
  GET    /api/evidence/all                Get all evidence

CUSTODY
  GET    /api/custody/:evidenceId         Get custody log for evidence
  GET    /api/custody                     Get all custody logs

TASKS
  GET    /api/tasks                       List tasks
  POST   /api/tasks                       Create task
  PUT    /api/tasks/:id/respond           Respond to task
  PUT    /api/tasks/:id/status            Update task status

FINDINGS
  GET    /api/findings/:evidenceId        Get findings for evidence
  POST   /api/findings/:evidenceId        Add finding
  DELETE /api/findings/:id               Delete finding

AI
  POST   /api/ai/summarize/:evidenceId    Generate AI summary via Groq

REPORTS
  GET    /api/reports/:caseId             Generate and download PDF report

9. SETUP AND RUNNING
================================================================================

  - Node.js v18+

  cd client && npm install

START BACKEND
  cd server
  node server.js
  --> Runs on http://localhost:5000

  --> Runs on http://localhost:3000

  --> Runs on http://localhost:4000

10. SECURITY FEATURES
================================================================================

  - Passwords hashed with bcrypt (12 salt rounds)
  - JWT tokens expire in 7 days
  - OTP expires in 10 minutes, single use only
  - Role-based middleware on all protected routes
  - File integrity verified with SHA-256 on every access
  - All evidence actions logged with IP address and timestamp
  - Avatar uploads restricted to image files, max 2MB
  - CORS enabled for cross-origin requests
